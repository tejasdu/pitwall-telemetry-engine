1. 📌 PROJECT VISION & EVOLUTION:
---------------------------------------------------------------------------------
High-performance, broadcast-grade Formula 1 Digital Pit-Wall & Strategy Intelligence
Engine. Designed as a real-time "second-screen companion" pairing alongside F1 race
broadcasts or historical race replays (2023–2026 seasons from OpenF1).

- v1 (COMPLETED on branch 'grafana'):
  * OpenF1 client ingestion, Pydantic v2 schemas, async replayer.
  * Basic strategy inferences (deceleration Δv/Δt, heavy braking, DRS proximity).
  * Redis 7 Streams message buffer with Prometheus exporter and Grafana dashboard.
  * Preserved and locked on branch 'grafana'.

- v2 (ACTIVE on branch 'live-pitwall'):
  * Replaces Grafana's 1-second polling bottleneck with a dedicated, single-window,
    broadcast-grade 60-120 FPS web application.
  * Full-Field Macro View: Dynamic 20-driver timing tower + 2D GPS circuit map.
  * Selective Micro View: Slide-up bottom telemetry drawer for 1-3 drivers.
  * Midfield Drama & Battle Detection: Automated detection of DRS attacks, dive-bomb
    overtakes, and DRS trains with one-click quick duel triggers.
  * Hybrid WebSocket streaming: Full 20-car positions + deep telemetry for active drivers.

3. ⚙️ TECHNICAL STACK & ARCHITECTURAL PIPELINE:
=================================================================================

- Backend Framework: FastAPI (Async ASGI) + Uvicorn
- Ingestion Client: OpenF1 REST API (httpx with 60s resilient timeout)
- Local Caching: In-memory / SQLite session cache to enable instant scrubbing
  without hammering external OpenF1 rate limits.
- Message Broker: Redis 7 Streams (sliding buffer MAXLEN ~ 5000)
- Transport: WebSockets (/ws/telemetry) pushing at 30-60 Hz with sub-5ms latency.
  * Bi-directional: Client sends driver selection / playback actions; server streams
    merged 20-car positions + deep telemetry for active drawer drivers.
- Frontend Engine: Vanilla HTML5 Canvas + Modern CSS (Zero heavy JS framework overhead).
- Physics Smoothing: Client-side Linear Interpolation (lerp, alpha ~ 0.15) for fluid
  60-120 FPS car gliding and analog gauge needles.
- Sporting Rules Accountability:
  * DRS threat calculations muted during Yellow / SC / VSC / Red Flag.
  * Delta-regulated sector times under caution excluded from true race pace calculations.

5. 🚀 PERFORMANCE OPTIMIZATION & FUTURE HORIZON ROADMAP:
=================================================================================

A. IMMEDIATE v2 CRITICAL OPTIMIZATIONS:
   1. Server-Side Disk-Backed Session Cache (openf1_client.py) [Scenario B - Cloud Architecture]:
      - Caches full session payloads (car_data, location, intervals, laps, stints) in server storage `.cache/sessions/{session_key}/`.
      - Lazy-Loading (Cache-Aside): When any user requests a new/uncached race, backend fetches once from OpenF1, saves to server disk, and streams.
      - Shared Multi-User Cache: Once fetched by User 1, all subsequent users (Users 2–1000+) are served from disk in <10ms with 0 OpenF1 API calls.
      - Zero Client Storage Overhead: End-users (browser/mobile) store 0MB locally; they only receive 60 FPS WebSocket frames.
      - Storage Footprint & Cost: ~25-45MB per race (~1GB per 24-race season), fits inside free 20-40GB SSD quotas on cloud VPS (AWS, Fly.io, Render, Hetzner).
      - Docker Persistence: Mount persistent volume to `/app/.cache` to preserve downloaded seasons across restarts/deployments.
   2. Unified Simulation Clock & Multi-Stream Alignment:
      - TimelineReplayer with synchronized T_sim cursor stepping at 30-60 Hz.
      - Aligns 100Hz car_data, 3.5Hz GPS, 0.05Hz intervals, and race control flags without desync.
   3. OffscreenCanvas Pre-rendering for Circuit Map:
      - Pre-render static circuit geometry spline and sector markers onto an offscreen canvas once.
      - On 60 FPS animation frames, blit cached background and draw 20 moving driver dots on top.

B. v2.1 PERFORMANCE & TRANSPORT ENHANCEMENTS:
   1. MessagePack / Binary WebSocket Protocols:
      - Compress high-frequency JSON payloads into binary byte arrays (60-80% bandwidth reduction).
   2. Client-Side Jitter Buffer + Lerp:
      - 2-frame buffer on frontend to ensure fluid 60-120 FPS car gliding even during network hiccups.
   3. Indexed Lap-Based Scrubber:
      - Pre-computed lap start timestamps for instant seek jumps (e.g., jump straight to Lap 24 restart).

C. v3 ADVANCED STRATEGY & AI HORIZON:
   1. Undercut / Overcut Pit Window Predictor:
      - Simulates ~20-24s pit lane loss against rival GPS intervals with estimated track rejoin position.
   2. Tire Degradation & Stint Pace Drop-off Model:
      - Lap time degradation curves per compound (S/M/H) vs tire age in laps to highlight pit windows.
   3. DRS Train & Overtake Probability Index:
      - Detects 3+ car DRS trains and predicts overtake likelihood based on delta speed at speed traps.
   4. Team Radio Audio & Live Transcript HUD:
      - OpenF1 /team_radio integration to stream driver audio clips and pop up real-time transcripts.
