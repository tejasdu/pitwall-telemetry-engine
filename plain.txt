2. Core Technical Components
    A. Dual-Driver Ingestion Engine (src/ingestion/)
        Mode A (Live Stream Poller): Queries OpenF1's /v1/car_data, /v1/location, and /v1/intervals endpoints. Uses an asynchronous leaky-bucket rate limiter to enforce the 3 req/s free tier cap.
        Mode B (Historical Replay Engine): Reads pre-fetched race datasets (e.g., 2024 Silverstone GP). Calculates timestamp deltas ($\Delta t = t_{i+1} - t_i$) and uses asyncio.sleep(\Delta t / multiplier) to push telemetry records sequentially into Redis. Supports 1x, 2x, 5x, and 10x playback speeds.
        
    B. Redis Message Buffer (src/storage/redis_client.py)
        Acts as an in-memory queue separating data fetching from calculation heavy-lifting. 
        Prevents API rate spikes from choking downstream processing tasks. 
        Retention policy configured with a moving TTL buffer (MAXLEN ~ 5000 items) to keep RAM usage minimal.
    
    C. Derived Metrics & Inference Engine (src/metrics/inferences.py)
        Transforms raw telemetry into high-value telemetry inferences: 
            1. Braking Delta Comparison: Calculates speed drop rate ($\Delta \text{speed} / \Delta t$) entering corner zones between driver pairs (e.g., Hamilton vs. Verstappen).
            2. DRS Attack Threat Detector: Evaluates time gaps (f1_interval). When a trailing driver's gap drops below 1.000s, the engine flips a binary gauge flag (1). 
            3. Tyre Degradation Estimator: Computes rolling average lap pace vs. stint age (laps on current compound: Soft, Medium, Hard).
            4. Pit Undercut Window: Evaluates if a driver pitting this lap rejoins ahead of a rival based on an estimated pit lane loss time of ~22.0 seconds.
            (AND MORE IF ADDITIONAL USEFUL METRICS CAN BE INFERED AND SHOWN)

    D. Prometheus Metrics Exporter (src/metrics/exporter.py)
